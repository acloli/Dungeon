# Test Spec — Vox Dungeon 首章闭环 MVP

- 日期：2026-05-06
- 绑定 PRD：`.omx/plans/prd-vox-dungeon-full-plan.md`
- 范围：首章 run、战斗、地图、奖励、商店、事件、Boss、结算、MasterData、UI 信息层级

---

## 1. 验收目标
1. 玩家可从主界面最小入口进入并完成整章 run；MainScene 的 meta 壳层不属于 MVP 验收主线。
2. 战斗规则满足：3 能量、5 手牌、出牌扣费、**TurnStart 展示敌人下一意图，EnemyTurn 执行已展示意图**、护甲/状态/胜败正确。
3. 20 张基础卡、升级派生卡、6 个遗物、5 类敌人/遭遇、事件、商店规则均由 MasterData 驱动。
4. 商店、奖励、事件、补给选择能正确回写 `RunState`。
5. 竖屏 UI 信息层级清晰，单手可完成所有核心操作。
6. 商业化入口不影响战斗数值。

---

## 1A. Gate 验收矩阵

### Gate A — Playable Gate
- 内容范围：**10 张基础卡（其中 8 张具升级分支）**、3 个遗物（`破损晶核` / `回音容器` / `裂纹圣像`）、3 类遭遇（`晶蚀鼠` / `废墟守卒` / `晶蚀王座残影`灰盒版）
- 页面范围：`HubPage` 最小入口、`MapExplorePage`、`BattlePage`、`RewardDialog`、`ResultPage`
- 必跑测试：`B-01 ~ B-08`、`B-10`、`R-01`、`R-02`、`UI-01`、`UI-02`、`3.0A` intent-lock 断言集、边界专项检查、数据完整性基础校验
- Exit Criteria：主线可跑通；Intent 时序稳定；`RewardResolver` 唯一回写生效；Boss 可完成基础战斗但可暂不启用正式 Phase 2 演出；不要求 `DeckPage` 与 `ShopSupplyPage` 进入主线

### Gate B — Content Gate
- 新增范围：补齐 20 张基础卡、其余升级派生卡、6 遗物、5 类遭遇、3 事件、`ShopSupplyPage`、完整 Boss Phase
- 新增必跑测试：`B-09`、`R-03 ~ R-07`、`D-02`、BossPhase 行为用例、设备矩阵 UI 用例、整章 walkthrough
- Exit Criteria：完整首章可玩；MasterData 全表校验通过；无 P0/P1 阻断；商业化红线检查通过

## 3. 核心验收用例

### 3.0 Playable Gate 升级池名单
- Gate A 固定实现 10 张基础卡：其中 8 张有升级派生、2 张无升级派生
- 有升级派生：`裂隙斩`、`晶片投射`、`晶壁格挡`、`预备架势`、`紧急偏折`、`能量虹吸`、`回响连斩`、`贯晶重击`
- 无升级派生：`晶髓修补`、`战术撤离`
- 命名规则：`<BaseCardId>_UP`

### 3.0A 意图/FSM 对齐断言
- `TurnStart` 结束时，必须已存在“下一敌方意图”的可见 UI 和日志记录
- `EnemyTurn` 执行的 `IntentId` 必须与上一个 `TurnStart` 记录一致
- `EnemyIntentState` 若存在，只负责演出，不得二次生成业务 intent

### 3.0B BossPhase 行为契约断言
- Boss 只有 2 个 Phase
- `HP > 50%` 为 Phase 1；`HP ≤ 50%` 为 Phase 2
- 阈值跨越在当前 Resolve 结束后切换，不打断当前卡牌结算
- 首次进入 Phase 2 时，仅触发 1 次：获得 8 护甲 + 锁定下一意图为 `高压连击(6x2)`
- 下一个玩家回合开始展示 Phase 2 的意图池


| ID | 场景 | 操作 | 预期 |
|---|---|---|---|
| B-01 | 战斗初始化 | 进入普通战斗 | 玩家 HP 正确、能量=3、手牌=5、敌人意图显示 |
| B-02 | 0 费牌 | 打出 0 费牌 | 不扣能量，效果正确触发 |
| B-03 | 1 费攻击 | 打出裂隙斩 | 能量 -1，敌人受伤 6 |
| B-04 | 能量不足 | 仅剩 1 能量时点 3 费牌 | 卡牌不可打出，UI 明确反馈 |
| B-05 | 状态效果 | 对敌施加易伤后攻击 | 伤害按易伤修正 |
| B-06 | 护甲清空 | 回合结束 | 玩家/敌人本回合护甲清空 |
| B-07 | 遗物触发 | 持有破损晶核进入战斗 | 首回合能量=4 |
| B-08 | 胜利判定 | 敌人 HP 降为 0 | 进入奖励流程 |
| B-09 | 失败判定 | 玩家 HP 降为 0 | 进入失败/结算流程 |
| B-10 | Intent 对齐 | 连续经历 TurnStart → EnemyTurn | EnemyTurn 执行的 intent 与上一轮已展示 intent 一致 |
| B-11 | Boss 转阶段 | 将 Boss 从 >50% 打到 ≤50% | 当前 Resolve 完成后切 Phase，触发一次 8 护甲并锁定下一意图为高压连击 |
| B-12 | Boss 一次性效果 | Boss 已进入 Phase 2 后再次跨阈值检查 | OneShot 不重复触发 |
| R-01 | 选卡奖励 | 战斗胜利后选 1 张卡 | 卡加入本次 run 牌组 |
| R-02 | 地图推进 | 选择下一节点 | `RunState` 进入对应节点 |
| R-03 | 事件奖励 | 触发事件选项 | 正确扣血/加钱/加卡/加遗物 |
| R-04 | 商店购买 | 购买卡/遗物 | 金币扣除，物品正确加入；若遗物超出 3 槽规则，触发丢弃流程 |
| R-05 | 补给强化 | 在补给点强化卡 | 已实装升级池内的卡升级为对应 `UpgradeToCardId` |
| R-06 | Boss 前补给 | 接近终点 | 必定出现补给节点 |
| R-07 | 章节结算 | 击败 Boss | 展示收益、本局摘要、返回入口 |
| D-01 | 数据完整性 | 启动数据校验 | 无缺失主外键 |
| D-02 | 商业化边界 | 检查商品表 | 无数值付费商品 |
| D-03 | 广告边界 | 检查广告入口配置 | 广告奖励仅产出局外货币，不影响 run 内战斗数值 |
| D-04 | 初始 loadout 边界 | 检查角色/初始 relic 配置 | 不存在通过付费获得更强初始战斗 loadout 的路径 |
| UI-01 | 战斗页可读性 | 进入战斗 | 敌人意图/能量/手牌/End Turn 明显 |
| UI-02 | 单手操作 | 完成一场战斗 | 核心操作均在下半区可达 |

## 4. 平衡性验证目标
- 普通战斗平均 3~5 回合结束
- 精英战斗平均 5~7 回合结束
- 首章通关时玩家通常能获得：
  - 4~6 张新增卡牌
  - 1~2 个遗物
  - 1~2 次强化/移除机会
- 极端差路线不应让 run 在第二节点前必死
- 低血玩家仍存在至少 1 条合理翻盘路径

---

## 4A. Walkthrough 与平衡采样协议
- Walkthrough 路线 A：保守路线（优先补给/防御）
- Walkthrough 路线 B：激进路线（优先精英/高风险事件）
- 每次平衡评估至少跑 10 局：保守 4 局、激进 4 局、混合 2 局
- 记录指标：通关率、平均回合数、平均剩余血量、平均新增卡数、平均获得遗物数、商店购买率

## 5. UI/UX 通过标准
1. 新用户 3 分钟内能理解：敌人意图、能量、出牌、结束回合、奖励选卡。
2. 战斗页无关键遮挡：意图/能量/手牌/End Turn 不被演出遮蔽。
3. 商店页无需滚动超过 1 屏即可看清核心商品。
4. 地图页节点类型识别准确，不依赖纯颜色区分。
5. 奖励页与结算页的主 CTA 均在拇指可达区。

---

## 6. 系统边界专项检查
- `BattleContext` 不直接修改 `RunState`
- `RewardResolver` 是 Battle/Event/Shop/Rest 写回 `RunState` 的唯一入口
- `PageFlowController` 不直接承担业务结算
- `SceneBridgeData` 只传摘要/引用，不复制完整战斗状态
- Boss Phase 表与 Enemy/Boss schema 键关联完整

## 7. 交付前回归清单
- M1 的 8 条战斗用例全部通过
- 整章完整 walkthrough 至少 3 次成功通关、3 次失败路径测试
- MasterData 全表静态校验通过
- 无 P0/P1 级死锁、断页、崩溃、无法结算问题
- 商业化表与 UI 入口通过红线检查
